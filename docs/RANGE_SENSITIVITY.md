# 行动历史范围推断与敏感性分析

2026-11-01 首版已实现，对应 [实施计划](RANGE_SENSITIVITY_PLAN.md) P1–P5；P6 跨手玩家校准尚未实施。

## 使用

在「精细分析」页打开「范围敏感性分析」。逐步记录模式中选择一名在局对手，输入明确的翻前先验（留空为全组合等权），执行分析。系统分别用基准、偏价值、偏诈唬模型重放本手历史；每个场景可查看具体组合权重、范围矩阵、牌型质量占比和逐次行动依据。

修改诈唬偏置后可以重算。也可选择「编辑已推断场景的当前范围」转入手动比较，继续修改范围文本。应用某场景到对手编辑器时保留逐花色权重，并标记为当前后验范围；不能把该范围重新当作同一手的翻前先验。

局面录入或旧记录缺失时，选择「手动比较当前范围」，直接比较各场景，不应用历史。指定明牌或已弃牌对手不能成为目标。

完整分析自动保存在独立浏览器存储项中，可恢复并重算，也可导出包含请求快照与结果的 JSON。导入始终交给服务器重新校验和计算，不直接显示文件中的旧结果。导入结果标记为历史快照，不应用到当前牌局。改牌、撤销、换手、改参数或换目标后，旧结果保留并标记失效。

后端新增了接口，已有服务进程需要重新启动以加载代码；前端开发服务器会自动刷新。

## 算法与边界

- 行动模型版本为 `history-rules-v1`，是启发式模型，尚未用真实牌局拟合或验证盈利能力。
- 基于候选手牌粗略成牌/听牌特征、位置、在局人数、压力、当街主动下注次数和可用有效筹码打分；合法动作 softmax 归一化，并乘以观察到的下注尺度分桶概率。概率下限通过分数权重加 `1e-4` 保留。
- 每次更新将该行动的对数似然加入组合对数权重，并减去最大值保持数值稳定。仅最后转换为现有引擎组合协议时裁剪低于相对最大权重 `1e-6` 的组合。裁剪概率质量超过 `0.0001`（0.01%）则拒绝计算。
- 强制盲注不作为行为证据。只使用该行动发生时的公共牌构建行为特征；分析时已知牌用于当前合法组合过滤，不视为对手当时掌握的信息。解释中的质量占比也以当前已知牌条件下的合法组合为基础。
- 后端重放并校验座位、行动顺序、投入、最小加注、短码全下、公共牌前缀与截止点。完整标记不能代替校验。缺少逐街牌面或完整历史返回输入不足；缺少开局筹码则跳过有效筹码规则并明确说明。
- 只推断选中对手；其他人的事件用于恢复上下文，其范围保持固定。权益继续按无牌冲突的联合权重计算。未对弃牌暗牌进行额外推断，也未求解完整多人联合行为模型。
- 同范围共用种子和权益缓存；不同范围从批次种子和场景 ID 派生独立种子。场景不保证权益单调。
- 价值/听牌/其他是粗分类，不表示对某个下注尺度已经校准的价值下注/诈唬比例。顺子、同花与牌面对全部玩家的共同成牌不等价于候选手牌独有价值。
- 精确枚举标准误显示 0；蒙特卡洛展示权益标准误。未提供跟注 EV 标准误，不声称统计显著或实际决策稳健。
- 有未建模的未来下注时跟注 EV 留空。边池沿用现有逐池条件及收益口径，不用单一权益阈值代替。没有加注 EV。

## 接口与保存兼容

新增 `POST /api/v1/sensitivity-analyses`、`GET /api/v1/sensitivity-analyses/{task_id}`、`POST /api/v1/sensitivity-analyses/{task_id}/cancel`。协议见生成的 OpenAPI；完整请求示例为 `examples/history-sensitivity.json`。

请求固定最多 5 个场景（界面默认 3 个），首场景 ID 为 `baseline`。历史请求需要显式开局参与座位、截止序号和在局座位映射。分析只读取截止序号以内的前缀。手动请求的每个场景需要当前范围，不能与历史推断模式混用。

任务共用原有有界进程池、任务数限制、TTL 和总时限。取消/超时保留已完成场景；未完成场景有独立原因。结果按 `complete / partial / none` 标记完成度。无可用权益时任务失败，但仍返回每场景诊断。原普通分析任务协议保持兼容，任务 ID 不能跨入口读取或取消。

新手牌保存 `handId` 和 `openingSeats`。旧存档如有起始筹码，可据此恢复开局参与座位；无此信息的旧档仍可继续使用普通分析和手动比较。范围文本上限从 12000 扩为 65536，支持现有无损逐组合序列化器完整保存推断结果，不把同类不同花色合并为最大值。普通场景保存版本仍为 3，新来源标记为可选字段；没有破坏性迁移。敏感性分析存档独立使用版本 1。

核心实现：`domain/history.py`、`domain/sensitivity.py`、`application/sensitivity.py`、`features/analysis/SensitivityPanel.tsx` 与 `useSensitivity.ts`。首版将特征、规则及更新集中在 `application/sensitivity.py`，没有提前拆分多层模型目录。

## 本地验证记录

Windows 10.0.26300，Python 3.11.13，Intel64 Family 6 Model 197；本地运行，非远程 CI 结果。

- 后端 111 项测试，其中敏感性分析 29 项，覆盖已知后验算例、逐街信息、阻断、长序列、合法动作、座位映射、短码盲注、截止点、去重、部分结果、取消、总预算、真实进程池和 TTL。
- 前端 80 项测试，ESLint、类型检查及生产构建通过。
- Microsoft Edge 下完整 31 项 Playwright 用例通过，包含新增历史推断与手动快照导入重算流程；已检查 390px 和桌面截图。
- 原 API 冒烟及新增 `scripts/smoke_sensitivity.py` 均通过。一次本地 HTTP 取消到终态观察为 29.1 ms，可能在排队阶段即被取消，不代表运行中取消的性能保证。
- Ruff、mypy、OpenAPI 快照和生成前端类型检查通过；本次新增/修改前端文件的格式检查通过。全仓 Prettier 仍报告既有 `LiveTable.tsx`、`LiveTable.module.css`、`tablePresentation.ts`、`tablePresentation.test.ts` 四个文件，不属于本次实现改动。
