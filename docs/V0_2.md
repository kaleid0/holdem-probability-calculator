# v0.2：加权范围与多策略比较

日期：2026-10-31。技术栈维持 React/TypeScript/Vite + Python/FastAPI/Pydantic + uv。

## 范围语法

| 输入 | 含义 |
| --- | --- |
| AA | 6 个 AA 组合 |
| AKs / AKo / AK | 同花 4 个 / 非同花 12 个 / 全部 16 个组合 |
| TT+ | TT、JJ、QQ、KK、AA |
| AJs+ | AJs、AQs、AKs；保留第一张高牌，逐步提高第二张 |
| AA-TT | 对子闭区间；两个端点顺序均可 |
| AJs-AKs | 高牌和花色类型相同的闭区间 |
| AsKh | 指定黑桃 A 与红桃 K 的单个组合 |
| AKs:0.5 | 各 AKs 组合相对权重为 0.5 |

牌点使用大写 `23456789TJQKA`，花色为小写 `shcd`。不同项用逗号、空格、分号或换行分隔。非对子必须高牌在前。非对子区间不跨越第一张高牌，不支持未明确列出的斜向区间语法。

权重为 0–1 的有限数，非零值最低 0.000001，以限制极端数值精度问题。默认权重为 1，零权重剔除；重叠组合取最大权重，因此 `AA,AA:0` 不代表移除 AA。移除操作请用矩阵或直接删除文本项。

矩阵单元格显示该类别内的最大组合权重；含部分具体组合时，文本保留其具体牌。切换、设置权重、移除是三种明确的点击模式。已知牌会阻断组合，但不会改写用户原始范围；界面有效数不代表多个对手之间的联合可行数。

### 滑块输入

主界面使用范围宽度（0–100%）、统一权重两个滑块，并提供 5%、15%、30%、50%、100% 快捷入口。细分选项可分别调整对子、同花、非同花的宽度，矩阵单格权重也使用滑块。文本输入折叠到高级选项中。

宽度使用项目内固定启发式分数排序，包含对子、牌点、同花和连张因素，仅用于快速输入，不是胜率排名或推荐策略。调整总宽度会替换原自定义范围；整类选入，原始覆盖率可能有少量取整差异。细分类别只替换对应类别。界面分别显示原始组合覆盖率、加权覆盖率和已知牌阻断数。

统一权重会覆盖原来的混合权重；原本等权时，整体同比缩放不改变归一化后的胜率。权重滑到 0 会清空当前输入，同一会话继续滑回非零可恢复刚才选中的组合。

范围语法、矩阵高亮和组合统计均本地即时计算，编辑期间不发送 preview 请求、不禁用有效矩阵。正式提交仍由 Python 后端独立校验。精确组合和自定义混合权重导入后保持原样，直到用户主动调整对应滑块。

## 分布与计算

移除已知牌后，每名玩家的范围保留独立权重。合法联合手牌的概率正比于各组合权重之积，再以牌不冲突为条件归一化。

- 小范围先建立合法联合组合表，按联合权重枚举或抽样，避免高冲突范围反复拒绝。
- 大范围使用独立抽取整组后拒绝冲突的方式，不逐玩家重归一化。
- 随机对手从选定范围后的剩余牌中无放回抽牌；公共牌随后从剩余牌中抽取。
- 准备、可行性检查及拒绝抽样均有预算；无解、过低接受率或超时会明确报错，不退回随机模型。
- 精确结果按权重累计；模拟误差按底池份额样本统计。多人平局仍按实际人数分摊。

## 两种策略

1. `pot-odds`：底池赔率基线，输出权益、赔率及单底池直接摊牌假设下的候选动作参考 EV。
2. `equity-rules`：权益余量规则，阈值为跟注所需权益加用户安全余量。余量范围 0–50 个百分点，默认 5。达到阈值偏向跟注，否则偏向弃牌。它是启发式偏好，不改变候选动作 EV，不代表盈利保证。

规则策略仅支持有跟注额、跟注后无额外投入的场景。缺少条件时该策略显示不适用，其他策略继续执行。当前只覆盖跟注/弃牌分析，不评估加注尺度或完整后续行动。

## 接口与兼容

保留 `/api/v1/analyses` 单策略请求。`schema_version` 接受 1 和 2；新界面发送 2。

加权对手可使用 `{"kind":"range","text":"TT+,AKs:0.5"}`，或 `{"kind":"range","combos":[{"cards":[44,48],"weight":0.5}]}`；两种表示不可同时提供。牌编码仍为 rank×4+suit，rank 从 2 到 A，suit 顺序 s/h/c/d。

多策略请求增加：

```json
{
  "strategies": [
    {"id":"pot-odds","config":{}},
    {"id":"equity-rules","config":{"equity_margin":0.05}}
  ]
}
```

提供 strategies 时按该列表执行，单独的 strategy_id/config 仅用于旧入口适配。最多选择 6 个不同策略，未知策略或单策略配置错误分别返回 outcome，不丢弃其他策略结果。

任务响应保留 result（首个成功结果），同时增加 outcomes 和 completion（complete/partial/none）。每个 outcome 包含策略 ID、状态、结果或原因；取消或超时也保留已经完成的策略结果。全部策略均无结果时任务状态为 failed。

结果新增 candidates、signals、策略配置、模型与引擎版本。候选 EV 明确使用筹码和“相对此刻弃牌”的基准；规则偏好不作收益排名。结果及场景保留各自版本。范围校验接口为 `POST /api/v1/ranges/preview`，输入 text/known_cards，返回总组合、阻断数、有效数、原始组合和类别最大权重。

同任务所有策略共享权益缓存、固定牌局、种子和总时限。缓存不跨任务持久化，键覆盖影响权益的请求字段，排除策略 ID/参数。阶段进度映射保证单调；TaskSnapshot 的 completed_samples/total_samples 在 v0.2 表示统一进度单位，真实状态或样本数量以每个 result.sample_count 为准。

保存文件升级为 schemaVersion 2，包含范围、多选策略和规则参数。v1 文件和旧 localStorage 场景可迁移；原 v1 存储键保留，新内容写入 v2 键。不修改用户磁盘上的旧导入文件。

## 验证与限制

本轮通过后端 62 项测试；滑块改进后，前端共有 20 项测试和 5 项浏览器端到端测试通过。覆盖快速连续点选、拖动、零权重恢复、类别独立修改、无 preview 请求以及精确输入保存。类型检查、静态检查和生产构建均通过。

验收覆盖：语法与权重、阻断、单组合/全范围等价、加权精确值与模拟、联合冲突及玩家顺序、无解的大范围、期限和取消、缓存与进度、部分失败、真实进程任务、v1 导入和 v2 保存、手机矩阵与页面无横向溢出。

浏览器测试使用本机已安装 Edge 的无头会话，CI 配置为 Playwright Chromium。CI 配置已写入，但远程 CI 尚未运行。上游测试客户端弃用提示和 Zod 构建注释提示仍存在，不影响本轮验证。

本机单次观测（Windows、Python 3.11.13、种子 42、一个加权范围、翻牌）20,000 次蒙特卡洛约 110 ms，约 182,000 样本/秒；引擎协作取消延迟约 1.2 ms。该记录包含范围准备，不包含 HTTP、排队、IPC、进程启动；仅为当前机器观测，不是服务响应时限承诺。可用 scripts/benchmark_v02.py 重现，原始记录写入 .local/v02-benchmark.json。

仍为本地单 API 实例和内存任务，不支持边池、抽水、ICM、GTO 求解器。v0.3 再增加完整玩家状态、位置、行动历史与合法动作。
