# 基于行动历史的范围推断与敏感性分析实施计划

日期：2026-11-01。状态：P1–P5 首版已实现并完成本地验收，P6 尚未实施。实际实现、兼容方式、验证及性能记录见 [功能说明](RANGE_SENSITIVITY.md)。下文保留实施设计和阶段验收基准。

## 1. 目标和首版范围

用户选择一个在局对手，系统根据本手行动序列推断其加权范围，自动生成「基准 / 偏价值 / 偏诈唬」三个场景，在固定牌局下比较权益及适用条件内的跟注 EV，并展示范围变化的依据。

首版只改变一个目标对手的行为模型，其他对手范围、公共牌、底池、投入与结算假设全部固定。支持当前逐步记录模式；快照模式仍能手动比较范围，但没有历史时不生成自动推断。模型为可解释的启发式模型，不宣称已经从真实牌局校准。

后续再接入稳定玩家身份、多手归档和个人习惯校准。首版不包含加注 EV、完整行动树、GTO 求解或自动学习上线。

## 2. 已有能力及缺口

| 现状 | 实施含义 |
| --- | --- |
| `frontend/src/handHistory.ts` 已定义有序行动和逐街公共牌事件 | 直接传结构化事件，不解析中文日志 |
| `LiveGame` 包含座位、庄家、盲注、可选起始筹码、`historyComplete` | 可建立本手上下文；旧档缺失信息必须显式降级 |
| `frontend/src/analysisRequest.ts` 已映射在局投入与底池上下文 | 扩展专用请求适配器，保留原普通分析入口 |
| 后端支持加权范围、阻断、合法联合分布和边池权益 | 复用现有权益引擎，不另建一个模拟器 |
| `AnalysisServices` 支持任务内权益缓存、时限和取消 | 批量场景共享预算，扩展阶段进度 |
| `TaskService`、worker 和任务快照目前以普通策略结果为中心 | 增加显式敏感性任务类型和结果封装，不能直接复用现有成功判断 |
| API 当前不接收行动历史；座位不是跨手身份 | 先补本手协议；跨手分析另建玩家档案与完整手牌归档 |

## 3. 数据流与协议

```text
冻结当前牌局及事件前缀
  → 校验历史并按时间恢复每次行动上下文
  → 确定翻前初始范围和模型参数
  → 分别用三个参数预设重放序列
  → 生成三个后验范围和解释记录
  → 在同一当前牌局上计算权益及允许的 EV
  → 汇总差异、误差、适用状态及决策稳定性
```

采用独立请求 `SensitivityRequest`，内含原 `AnalysisRequest` 作为 `base_analysis`，不改变旧请求默认行为。新增字段如下，字段名称在 P1 冻结：

- `history_context`：历史协议版本、本手标识、分析截止事件序号、是否完整、开局参与座位、庄家、盲注、可选开局筹码及完整事件前缀。开局参与座位必须单独记录，不能由当前弃牌列表反推。
- `seat_mapping`：本手座位到 `base_analysis.opponents` 下标的显式映射；英雄固定座位 0。已弃牌玩家仍保留其历史事件和投入，但不成为在局权益对手。
- `target_seat`：唯一目标在局对手。指定明牌对手不支持自动推断。
- `prior`：来源、版本及翻前初始组合；自动预设必须显示来源。用户输入明确标记为「翻前先验」或「当前范围」；当前范围不能再从翻前重复更新。
- `model`：模型 ID、版本及三个场景的参数快照；首版最多 3 场景，预留上限 5，不接受任意可执行表达式。
- 预算与种子：沿用原样本量语义（每个场景的目标样本数），另有整个批次的总时限；界面显示场景数和预算，不把每个场景各自分配完整任务时限。

结果 `SensitivityResult` 保存请求哈希、模型版本、历史截止点、先验来源、目标座位、输入质量、场景结果和批次摘要。每个场景包含：

- 参数、后验范围快照、有效组合数、范围熵/有效组合质量等可选诊断；不把组合数当成范围强度。
- 按行动的解释：事件序号、当时公共牌、特征、规则 ID、参数和变化前后牌型质量占比。详细到单组合的跟踪按需返回，避免结果体膨胀。
- 原 `AnalysisResult` 中适用的权益、逐池预期所得、EV、计算方法、标准误和样本数。
- 相对基准的权益差（百分点）、同口径 EV 差；基准失败时差值为 null。
- 独立状态 `ok / insufficient-data / unsupported / error / timed-out / cancelled` 和原因，不用 0 表示未计算。

新增接口：`POST /api/v1/sensitivity-analyses` 返回 202 与任务 ID；对应 GET 查询和 POST cancel。与旧任务共享有界队列、进程池和 TTL，不另起无界任务系统。扩展任务类型和 worker 分派，敏感性结果通过独立快照模型返回，原分析响应保持兼容。同步 OpenAPI 快照和前端生成类型。

## 4. 推断算法和模型约束

### 4.1 逐次更新

对每个目标手牌组合 h 和目标自愿行动 a，内部更新：

```text
log_weight_next(h) = log_weight_previous(h)
                   + log P_model(a | h, 当时的牌局上下文, 场景参数)
```

首版用可配置规则给合法动作打分，再通过 softmax 转为该决策点上合法动作类别的概率。下注/加注尺度使用固定分桶的条件概率；在同一分桶定义下比较各组合，不把连续金额的任意打分称作已校准概率。给非强制动作概率设置版本化的小正下限，避免一条启发式规则永久排除所有其他可能。强制盲注不作为打法证据。

规则参数首版必须写出取值、依据和适用条件，随代码版本管理。首批规则至少覆盖翻前首次加注/跟注/再加注，以及翻后过牌、跟注、下注、加注；不支持的特殊上下文返回原因，不通过未知分支悄悄缩窄范围。

特征使用位置、在局人数、当前街、面对的下注、相对底池尺度、有效筹码、公共牌结构，以及候选手牌在当时的成牌、听牌和阻断特征。有效筹码需要完整开局筹码与累计投入；缺失时跳过相关规则并说明。bet 使用 `amount / potBefore`；raise 单独定义加注增量与跟注后底池的尺度，不能把 `amount` 或 `streetTotal` 直接当纯加注量。零底池单独处理；短码全下不等于完整再加注。

只使用每次行动前已公开的牌构造行为特征，不能用转牌解释翻牌行动。英雄手牌和分析时已知死牌用于当前结果的合法组合过滤，不作为对手决策时可见信息。未公开的指定对手牌同理。街事件缺失公共牌时不从最终牌面猜测，应返回输入不足。

使用 log-sum-exp 归一化避免长序列数值下溢；手工先验的零权重保持为零。输出到现有权益引擎时按最大值缩放，低于 `1e-6` 的正权重按明确规则裁剪并重新缩放，报告被裁剪的归一化概率质量；质量超过版本化阈值则中止并报数值精度不足。不得在每次行动后提前裁剪。P1 固定并测试裁剪阈值。

### 4.2 三个自动场景

三个场景复用同一先验，分别在整段历史上重放不同的行为模型参数：

| 场景 | 参数含义 |
| --- | --- |
| 基准 | 使用版本化默认行为模型 |
| 偏价值 | 降低弱牌及合理诈唬牌采取主动下注/加注的概率 |
| 偏诈唬 | 提高合理诈唬牌采取主动下注/加注的概率 |

调整一个动作类别后必须重新归一化合法动作概率。成牌与诈唬标签随公共牌和下注语境变化，不使用固定的「某张牌就是诈唬」。未触发相关规则时三个范围可能相同；返回「该序列无法区分这些假设」，合并重复计算，不人为制造差异。场景权益也不承诺单调。

首版对其他玩家行动只恢复牌局上下文，不利用其历史额外推断其范围；每个场景的目标范围和其他固定范围，仍由现有引擎按无冲突联合权重计算。明确这是近似的单目标推断，不是完整的多人联合贝叶斯模型。

## 5. 输入质量、误差及决策摘要

- 完整历史才开放自动全序列推断。`historyComplete=false`、旧中文日志、缺失逐街牌面或不一致事件返回 `insufficient-data`，保留手动范围比较入口，不默认补全行动。
- 后端校验序号、街顺序、牌面前缀、金额与当前底池的一致性、座位映射及投入关系；通过重放校验历史，不能只相信客户端的 `historyComplete=true`。
- 缺少筹码时允许仅使用不依赖筹码的规则，结果注明降级；输入完整度不是模型准确率，不显示未经校准的「置信度 90%」。
- 撤销、换手、改牌、修改范围或切换目标后，新输入哈希使旧结果失效。结果明确绑定请求快照，旧任务返回不得覆盖新牌局。
- 总预算涵盖校验、推断、所有场景计算和汇总；推断循环也检查取消。场景异常不丢失已完成结果，预算耗尽后未运行场景标记 `timed-out`。
- 取消后保留已完成场景，任务状态为 cancelled；完成度分别为 complete/partial/none。失败场景不参加稳定性结论，未全部完成时摘要必须注明不完整。
- 精确枚举标准误为 0；模拟结果按引擎的底池份额误差报告。固定种子用于复现，不认为同种子足以消除场景差值噪声。
- 首版可使用独立场景种子，由批次种子和场景 ID 稳定派生；差值误差按独立样本处理，重复范围从缓存得到相同结果时差值为 0，不套独立误差公式。以后再考虑配对抽样。
- 跟注 EV 继续由现有策略判断适用性；存在未建模未来下注时 EV 为 null，不生成加注 EV。边池不能套用单一总权益阈值，沿用逐池计算口径。
- 首版使用近似 95% Monte Carlo 区间辅助标注：任一 EV 区间覆盖 0，标「临界/模拟精度不足」；所有有效场景均显著同号，标「在所选假设下方向一致」；出现显著正负两侧，标「依赖范围假设」。该区间只描述模拟误差，不包含模型误差；多场景不作为联合统计保证。EV 的误差必须来自实际回报样本，不能拿普通权益误差直接套用于边池。
- 如引擎尚未提供对应 EV 标准误，先仅展示权益误差与 EV 点估计，摘要不使用「显著」或统计稳定性措辞。场景区间是人工选定假设集合的结果包络，不是实际范围的概率置信区间。

## 6. 分阶段任务与验收

按 P1 → P2 → P3 → P4 → P5 顺序交付，每阶段可独立审查。P6 是后续扩展，不阻塞首版。暂不承诺日历工期；P3 实测批次耗时后再决定默认样本量和预算。

| 阶段 | 主要改动 | 交付与退出条件 |
| --- | --- | --- |
| P1：冻结历史与分析协议 | `handHistory.ts`、`liveGame.ts`、`sessionStorage.ts`、请求适配器；新增 `domain/history.py`、`domain/sensitivity.py`；OpenAPI 与生成类型 | 明确开局座位、历史截止点、映射、先验语义、误差口径与数值阈值；版本化协议及合法/缺失/错误请求样例；旧分析和旧存档继续可用 |
| P2：可解释范围推断 | 新增 `inference/features.py`、`inference/rules.py`、`inference/update.py` 和可信模型配置 | 从先验与序列得到确定性后验；三个模型预设及逐事件解释；无未来信息泄漏、无盲注证据、无重复应用历史；缺失输入明确降级 |
| P3：批量权益及任务 | 新增 `application/sensitivity.py`；扩展 `tasks.py`、`compute.py`、`services.py` 和 API | 三场景复用现有引擎；共享总预算、去重、取消、部分成功、可复现哈希；旧策略任务不受影响；记录真实性能 |
| P4：界面与保存 | 新增 `features/analysis/SensitivityPanel.tsx`、专用请求与轮询 hook；扩展 `RangeEditor` 预览能力和保存协议 | 选目标→确认先验→自动推断→对照结果→查看依据；允许手动修改派生场景；撤销/换手使结果失效；保存导入可复现，旧存档迁移通过 |
| P5：集成和发布验收 | 后端、前端、API、浏览器验收，新增示例和使用说明 | 所有质量检查通过；固定案例、异常案例、性能及边界文档齐全；首版功能才标记完成 |
| P6：跨手玩家校准 | 稳定玩家 ID、完整手牌归档、机会统计、模型校准及评估 | 先交付可核对统计，再用独立留出数据验证模型；未通过则继续使用默认模型，不阻塞 P1–P5 |

### P1：协议先行的具体任务

1. 补充开局参与座位快照及持久化版本，明确旧档迁移后哪些信息不可恢复。
2. 定义历史重放结果和特征输入；所有字段标明行动前/后、金额是追加还是加注至。
3. 固定自动先验来源：首版使用可解释、带版本的手工翻前先验；没有位置模板时使用明确标记的全组合等权先验，不伪装成已验证翻前表。
4. 固定三场景参数及支持矩阵，分别定义无筹码、多人底池、短码全下、空历史和仅盲注的行为。
5. 提交请求/响应示例、错误码及任务状态转换说明，同步 OpenAPI 和生成类型。

### P4：界面行为

- 自动推断前显示目标对手、历史覆盖街数、先验来源和模型版本。没有完整历史时显示具体缺项。
- 结果表包含场景、价值/听牌/其他牌质量占比、有效组合数、权益及误差、权益变化、可用 EV 与状态。牌型分类规则写明，不能用矩阵格数代替组合权重。
- 解释抽屉按时间显示「翻牌跟注」「转牌加注」等规则证据，不只展示一个最终标签。
- 派生范围保持独立，默认不覆盖原范围；用户显式选择应用后才更新编辑器，并记录「当前范围」来源以防重复推断。
- 首版可在只读矩阵显示具体组合权重与类级汇总；现有文本编辑器无法无损表达逐花色后验，不能把同类组合取最大值后覆盖保存。持久化扩展组合形式并兼容旧文本范围。
- 参数或派生范围修改后，场景标记为自定义，差异和结果重新计算；加载保存结果时核对引擎/模型版本，旧版本结果作为历史快照显示。

## 7. 验收案例和检查方式

### 推断与协议

1. 人工两组合算例：先验各 0.5，某行动似然分别为 0.8/0.2，后验应为 0.8/0.2；两次更新符合乘积归一化。
2. 只有盲注或各组合行动概率相同时，合法先验的相对权重不变；所有规则的合法动作概率和为 1。
3. 同一翻牌事件在不同后续转牌记录中，其行为特征相同；最终范围可因新公开牌阻断而变化。
4. 事件截止点之后的行动不得进入推断；重复提交、刷新和撤销后重算不会重复乘似然。
5. 阻断、先验为零、近零权重、长序列、全范围冲突、低于精度阈值均有确定行为。
6. `raise` 的追加/加注至、短码全下、零底池、单挑位置、多人及空座位映射覆盖；无筹码旧档不编造有效筹码。
7. 缺公共牌、事件乱序、金额不符、目标已弃牌、指定明牌目标、已知牌冲突及不完整日志返回可操作原因。

### 权益、任务与界面

1. 同一推断范围单独提交普通分析，与敏感性对应场景在相同计算设置下结果一致；小型范围用精确枚举基准核对。
2. 三个范围相同只计算一次；基准失败时不生成相对差值；全部失败不标成功，部分成功保留结果。
3. 取消和超时覆盖推断、枚举、模拟及场景间切换；进度单调；队列上限与 TTL 沿用现有约束。
4. 无未来下注和有未来下注分别检查 EV 是否可用；边池按现有逐池口径验证；未来下注时不得出现完整行动 EV 建议。
5. 旧普通分析、多策略比较、随机/明牌/加权范围、场景导入导出及边池回归通过。
6. 浏览器覆盖完整逐步记录、目标切换、查看依据、手工调整、撤销、换手、恢复存档、旧结果晚到及窄屏显示。

实现检查沿用项目工具：后端 `uv run pytest`、Ruff 与 mypy；前端 `pnpm check`；Playwright 覆盖上述主要流程；`scripts/export_openapi.py` 与前端 `api:generate` 后检查契约差异，并扩展真实 HTTP 冒烟。

性能记录至少包含测试环境、输入范围数、合法组合数、场景去重数、实际样本数、总耗时、取消响应时间和超时比例。精确枚举案例与蒙特卡洛案例分别记录，不预先承诺未经测量的延迟。

## 8. P6：跨手历史的后续实施

当前筹码账本只记录投入、收回和结余，不能用于统计完整行动。先在新手清空事件前归档不可变手牌记录，包含 hand ID、每座位当手 player ID、开局状态、完整事件、已公开摊牌和数据完整性。换座/换人必须显式绑定，不能按同号座位自动合并玩家。

统计首先覆盖 VPIP、PFR 和有机会面对加注时的再加注频率，每个指标显示分子、机会数及缺失覆盖；强制盲注不计自愿入池，弃牌且未摊牌的手牌也计入适用机会。使用版本化总体先验收缩个人统计，避免少量样本主导模型。

行动频率只能校准总体松紧与进攻倾向，不能单凭这些频率识别具体牌型下的行动概率。摊牌数据另标其选择偏差；训练与留出按手牌/时间拆分，不能将同一手不同动作拆到训练和测试两边。校准模型与默认模型比较可观察行动的预测损失，并在可用摊牌样本上做有偏差说明的范围诊断；没有独立验证时不声称准确率提升。

个人校准未达预先定义的有效机会数和离线评估标准时，继续使用默认模型，并展示数据覆盖。阈值在 P6 协议阶段冻结，不从当次分析的输赢反向调整参数。

## 9. 首个实施切片

从 P1 开始，先交付「一段完整的本手历史 + 一个目标对手 + 手工翻前先验」的版本化请求/响应样例、后端校验与前端适配，再进入 P2 推断。首版以 P1–P5 全部退出条件通过为完成标准；P6 单独验收。
