# 行动建议引擎实施计划

日期：2026-11-02。状态：待实施。依据：当前已完成的后端决策迁移，见 [职责边界](BACKEND_DECISIONS.md)。本文记录下一阶段计划，任务完成前不视为已具备对应能力。

## 目标与现状

目标：在明确的对手范围、行为假设和合法动作集合下，比较同一口径的候选行动收益，输出动作、投入金额、理由与稳定性；逐步让跨手对手习惯改变范围和响应概率，再重新计算 EV。

已具备：

- 精确／蒙特卡洛权益、加权范围、已知牌阻断、多人无冲突联合抽样及分池收益。
- 本手行动范围更新、单挑河牌条件跟注范围及翻牌／转牌有限行动树。
- 后端建议入口、历史重放、结构化动作与金额、来源校验、模型优先级及启发式回退。
- 前端任务取消、旧建议失效与迟到响应隔离。

主要缺口：范围推断与未来响应使用分散规则；通用行动 EV 的响应与手牌独立；跨手玩家身份、完整归档和可学习行为模型尚未建立。

本轮先覆盖单挑河牌，在原有适用条件下替换响应内核。多人非终局、完整多街求解、连续金额优化、GTO、锦标赛 ICM 留待后续；现有多人权益、边池分析及教学回退继续保留。

## 实施顺序与里程碑

| 阶段 | 交付 | 依赖 | 完成标志 |
| --- | --- | --- | --- |
| S0 | 冻结接口与模型边界 | 已有后端迁移 | 明确比较口径、模型快照、旧行为回归样例 |
| S1 | 共享行为模型及河牌接入 | S0 | 历史范围更新和河牌未来响应经过统一接口，旧模型可复现 |
| S2 | 河牌条件 EV 与稳定性建议 | S1 | 同一响应分布生成弃牌率、条件跟注范围及候选 EV，主建议可解释 |
| S3 | 玩家身份、多手归档与行为统计 | S0；个性化使用前必须完成 | 可重放、去重、修正和按机会统计，重启后可恢复 |
| S4 | 个性化响应与离线校准 | S2、S3 | 小样本平滑、模型快照、按时间评估及回退可用 |
| S5 | 扩大加注和有限树覆盖 | S4；也可先用默认行为模型试验 | 新增动作分支有条件范围、合法金额及独立验收 |

默认交付顺序为 S0 → S1 → S2 → S3 → S4 → S5。每阶段独立合并、保持可运行。S3 的数据归档可在 S0 后提前启动积累，不能因此提前启用未经验证的个性化建议。

第一个可发布里程碑为 S0–S2；第二个为 S3–S4。S5 按覆盖场景分别交付，不作为前两个里程碑的前置条件。

## S0：冻结比较口径与可复现输入

### 工作项

1. 沿用 `domain/advice.py`、`application/advice.py` 和现有策略协议；把统一建议入口视为已完成基础，不重复建设。
2. 为候选比较补充机器可读的模型说明：收益目标、决策起点、终止条件、后续策略、候选集合与缺失分支。直接摊牌、有限树与启发式分别标识，不跨口径排序。
3. 明确 `AdviceAction.amount_kind`：跟注使用追加额，加注使用本街加注至金额；保留候选实际追加额。全下作为动作的筹码状态表达。
4. 设计行为模型快照：模型 ID／版本、参数摘要、玩家画像版本、训练数据截止点、先验版本、特征版本和情景 ID。新增字段采用兼容默认值，接口变更同步 OpenAPI 和前端类型。
5. 建立固定决策样例，保存输入、历史截止序号、随机种子、模型配置及预期性质。快照能独立于短期内存任务 ID 复算。

### 验收

- 相同输入、快照和种子可复现；修改行动、范围、画像或响应配置后，旧结果不能匹配新建议。
- 保留现有金额记账、非本人行动、历史篡改、任务过期、取消、边池和短筹码边界。
- 冻结迁移后当前行为，后续模型变化能够明确归因。

## S1：共享行为模型，先接入单挑河牌

### 建议模块边界

以下路径为拟新增或调整的位置，最终按实现需要细分。

| 模块 | 职责 |
| --- | --- |
| `domain/behavior.py` | 模型快照、行动前上下文、合法响应与尺度分布合约 |
| `engines/behavior.py` | 默认规则模型、概率归一化与模型选择 |
| `application/sensitivity.py` | 用共享模型评估已发生行动及尺度的似然 |
| `application/river_response.py` | 将现有河牌跟注规则封装为默认响应实现 |
| `application/river_inference.py` | 消费响应分布，构建条件范围与候选收益 |
| `application/services.py` | 向策略注入已经冻结的模型依赖 |

### 工作项

1. 定义联合似然 `P(action, size_bucket | candidate_hand, actor_context, model_snapshot)`；对未来给定我方候选动作，返回对手合法响应分布。离散动作与尺度分桶均需明确归一化规则。
2. 上下文从重放恢复的行动前状态构造，包含位置、街道、公共牌、人数、跟注成本、有效筹码及之前行动。已观察的下注尺度作为似然目标，不能同时当作预测该尺度的输入。
3. 将现有历史 softmax 规则和河牌跟注曲线封装为版本化默认实现。第一步允许不同节点采用不同规则内核，但经统一接口和快照调用，保留原参数及原概率。
4. 第一批接入历史范围推断和河牌响应。有限树在 S5 接入，其旧模型依赖在结果中继续标明。
5. 手动当前范围直接作为当前分布使用；翻前先验才重放本手行动。重算与撤销从正确先验重建，不能重复累乘后验。

### 验收

- 合法响应概率非负、有限且总和为 1；不合法动作概率为 0。
- 默认配置在原适用场景与旧结果一致；不能为了统一接口悄悄增加再加注分支。
- 响应预测仅使用行动者可知信息与其候选私牌；不向对手泄漏我方底牌、私有死牌或未来公共牌。范围抽样仍可使用观察者已知牌排除冲突。
- 玩家参数改变能够改变对应行动似然和未来响应，而不是修改最终建议文字。

## S2：河牌条件收益与建议稳定性

### 工作项

1. 在现有完整历史、单挑、对手已过牌、自己最后行动、无需跟注且无边池的河牌场景中接入共享响应模型。继续比较过牌和现有合法候选下注金额。
2. 对每个候选金额、每个对手组合计算弃牌／跟注概率，由同一联合分布求出弃牌率、跟注条件范围及被跟注权益；禁止独立指定互不一致的弃牌率和跟注范围。
3. 把模型来源、样本／数据支持、关键假设、未覆盖动作、各情景 EV 与相对过牌收益返回给建议解释层。
4. 为比较结果提供稳定的候选 ID；建议及 `best`／`stable` 的内部匹配采用 ID，中文标签只用于展示。保持旧客户端兼容字段直到迁移完成。
5. 沿用 `application/advice.py` 的适用模型优先级。只有同一模型内的合法候选可按 EV 比较；旧独立响应 `comparison` 继续标明来源，不参与跨模型排名。
6. 基准与压力情景分别重算条件范围及响应。抽样临界使用候选收益差的误差，适用时复用配对样本；规则假设的情景包络单独展示。

### 记账与稳定性约定

- 当前底池 `P` 已含对手当前投入。当前决策后自己的新增成本才从收益扣除，未匹配筹码退回。
- 无需跟注且对手仅弃牌／跟注时：`EV(bet) = F*P + (1-F)*(E_call*(P+2B)-B)`。
- 已面对下注、跟注成本为 `C`、本次总追加为 `R` 时，若对手只跟注：最终池为 `P+2R-C`。该记账约定用于 S5 的加注分支。
- 精确枚举没有蒙特卡洛误差，不代表范围或行为假设准确；偏紧／基准／偏松结果一致也不转换成“建议正确率”。
- 再加注尚未覆盖时明确给出终局跟注／弃牌模型假设。需要该分支的分析保持未覆盖状态，不把其概率偷偷归到跟注。

### 验收案例

- 所有组合弃牌、所有组合跟注、公共牌强制平局、我方确定赢／输时，收益可手算核对。
- 较强组合更常跟注时，条件权益与原范围权益正确区分。
- 人工构造一个牌局：在两组合法且明确的默认／偏弃牌响应假设下，过牌与下注的 EV 排序发生预期变化。
- 情景建议翻转时显示敏感；收益接近抽样误差时显示临界；只有过牌候选时说明未比较下注。
- 保留手机展示、快速连续修改、迟到响应、模型失败重试及旧结果隐藏的浏览器验收。

### 运行约束

条件范围、枚举和模拟仍放入现有分析策略与有界进程池。`POST /api/v1/decision-advice` 只校验和解释已完成结果；切换影响高级分析的响应参数须提交新任务。

任务、缓存和建议来源校验同时绑定局面、历史、模型快照及响应配置，不能只改变建议请求中的参数而继续引用旧高级结果。模型快照必须可序列化并传入工作进程。

在同一机器、同一数据集记录现有与新模型的计算耗时、端到端延迟、取消延迟和内存；遵守现有任务总时限及样本预算。模型接口接入的等价运行若耗时增加超过 20%，先定位原因再切换默认；该数值是本项目验收门槛，不是跨机器性能承诺。

## S3：玩家身份、多手归档与统计

### 工作项

1. 新增稳定 `player_id` 与每手座位映射。用户可选择已有玩家、创建玩家或使用仅本桌有效的临时身份；新玩家不继承原座位的画像。
2. 定义版本化归档：`hand_id`、修订号、牌桌／玩家映射、开局筹码和盲注、庄位、有序事件、公共牌、已观察底牌及观察来源、结算结果、完整性标记。
3. 增加后端存储协议，首版采用本地 SQLite 持久化；数据库放在运行数据目录，不提交仓库。读写与领域统计分离，保留导出／导入能力，前端当前手保存继续用于即时恢复。
4. 在结算／进入下一手前归档；自动结束的牌局也走同一入口。浏览器离线或请求失败时保存持久化待同步记录，重启可重试；相同 `hand_id + revision` 幂等，内容冲突拒绝覆盖。
5. 牌局修正或撤销结算后提交新修订／撤回标记；统计只使用每手最新有效版本。归档完成后方可清除待同步记录，不因重试重复计数。
6. 从重放推导每项统计的行动机会及结果。先做 VPIP、PFR、3-Bet、Fold to 3-Bet、C-Bet、Fold to C-Bet；后续再补 WTSD 等指标。
7. VPIP／PFR 按合格手数去重；盲注不算自愿投入。3-Bet 指首次加注后的再加注，各项分母使用对应行动机会。C-Bet 需校验之前主动权及当街下注机会。

### 验收

- 同一玩家换座位保持身份，新玩家入座不会混用画像。
- 下一手、刷新、服务重启后历史可恢复；重复上传、离线重试、修正、撤销不会重复统计。
- 全下、强制盲注、未完整记录、无人摊牌和缺少底牌分别处理；实际赢家不作为底牌标签。
- 用人工标注的完整多手事件，逐项核对分子和分母。旧存档可继续录入，缺失历史不补造训练样本。

## S4：个性化响应与模型校准

### 工作项

1. 先学习可直接观察的 `P(action | context, player)`，例如面对特定尺度下注的弃牌频率。使用粗粒度街道／位置／压力分桶，稀疏桶回退到更粗上下文。
2. 二元频率用 Beta-Binomial 平滑，多动作分布用 Dirichlet 平滑；显示对应机会数、先验来源及估计区间。先验强度和分桶作为版本化配置。
3. 首版以默认条件模型为基础，拟合有收缩约束的玩家行动偏置；对隐藏手牌求和计算观察行动的边际似然。不能把总体弃牌率当成对每个组合相同的弃牌概率，也不能据此声称已经识别真实诈唬率。
4. 参数不足以识别时保留先验及模型敏感性。已知底牌样本可辅助校准，但需单独报告摊牌选择偏差；不把本系统推断的手牌当真实监督标签。
5. 在分析任务创建时冻结模型参数和画像版本，仅使用目标手之前的有效历史；本手证据用于本手范围更新，归档后才用于后续画像，避免同一证据重复使用。
6. 默认模式与个性化模式通过替换概率模型后重算 EV 实现。无画像、数据质量不足、校准不通过或快照不可用时，返回明确原因并使用默认模型。

### 校准与启用门槛

- 按整手和时间切分训练、验证与保留测试集；同一手的事件不跨集合。所有特征还原到行动发生之前。
- 比较默认模型和平滑个性化模型的行动对数损失、Brier 分数、校准曲线及按街道／玩家的数据覆盖；不以某手输赢判断建议正确性。
- 先在未参与拟合的合成对手上检验收缩、可复现及已知倾向，再用有足够覆盖的真实归档验证。合成通过不替代真实校准。
- 默认自动启用前，个性化模型须在保留集上改善行动预测，按手重采样的不确定性评估支持该改善；样本量、分桶覆盖和区间宽度不足时保持试验状态。
- 新增决策案例验证“响应变化 → 条件范围变化 → EV 变化 → 建议变化”的完整链路。收益改善只能在明确测试对手与环境内报告。

## S5：扩大动作与未来收益覆盖

按以下顺序单独实现、验收：

1. 将有限树中的对手行动规则接入共享模型，保留当前树深和我方固定应对，再比较替换前后结果。
2. 增加单挑河牌面对下注的弃牌／跟注／候选加注；每个尺度展开对手弃牌、跟注、再加注及我方明确应对。默认只允许有界次数再加注，到全下直接结算，树的截断规则显式返回。
3. 扩展翻后前位与更多后续动作。未来我方决策仅基于当时可知信息及后验范围，不按抽到的对手底牌或最终胜负逐样本选择动作。
4. 评估多人非终局与边池行动树的成本后，再单独制定覆盖计划。已实现的多人摊牌权益不视为完整多人行动 EV。

每次扩展都补充合法动作、最小加注、重新开放加注权、有效筹码、退款、条件范围及误差对照。固定候选尺度内的最高 EV 只表示该候选集与指定后续策略下最优。

## 发布、回退与工程检查

- 每阶段以独立模型版本／配置启用；保留当前默认规则模型，支持复算旧快照。输入错误、旧任务失效及历史不一致按现有协议返回，不用回退掩盖错误。
- 个性化模型不可用可回退默认概率；超时或不支持的行动树回退到明确标记的已支持建议，禁止继承已过期动作。
- 显示顺序保持动作与金额、主要理由、稳定性在前；模型细节、样本量及候选 EV 可展开，不增加基础计算必填项。
- 变更领域／引擎后运行相应后端回归、Ruff 和严格 mypy；API 变更导出 OpenAPI、生成前端类型并检查同步。
- 前端运行 `pnpm --dir frontend check`，交互变更补充相关浏览器流程；高成本引擎变更记录基准和取消行为。具体命令沿用 [项目说明](../README.md)。
